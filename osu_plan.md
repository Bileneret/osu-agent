# osu!-агент — план проекта (рабочий план, v2)

**Дата:** 19.10.2026. **Статус:** план составлен по ответам пользователя на 50 вопросов (см. §3);
после утверждения — создание репозитория и старт спайка.
**Контекст:** составлен после заморозки MCP-Hands (`D:\BOT\MCP-Hands`, тег `v0.9-frozen`,
репозиторий опубликован: https://github.com/Bileneret/mcp-hands). Опирается на разбор
варианта №1 от 16.10 (идея перепроверкаа), замеры машины пользователя от 19.10 и наработки MCP-Hands.

---

## 1. Что строим

**Frame-Perfect агент для ритм-игры osu!**: агент сам играет карту — читает карту из файла,
синхронизируется со звуком и точно ставит удары, ведёт курсор по слайдерам.

**Финальная демо-цель (решение пользователя):** карта на 10 звёзд, пройденная на 99%+ —
лайв-демо для репозитория. Это цель-максимум; к ней идём поэтапно (§10), промежуточные
критерии жёсткие, но реалистичные.

Промежуточная цель: **100% попаданий (0 miss) сначала на всех картах без слайдеров
(только круги), затем на всех картах со слайдерами и остальным.**

Это **инженерный полигон и вау-демонстрация**, а не «чит для таблиц»: играем офлайн,
на картах без рейтинга, рекорды не отправляем, клиент не модифицируем и в память процесса
не лезем — работаем **снаружи**: экран, звук, ввод.

## 2. Границы и этика (жёстко)

- **Только офлайн.** Никаких матчей с живыми игроками, никаких мультиплеерных комнат.
- **Выход из аккаунта на весь проект** (решение пользователя, Q14=А): карты и всё сетевое —
  скачать/сделать ДО выхода; после выхода lazer не сможет отправить ни один результат.
  Это единственная железная гарантия границы (прочие варианты — ненадёжны: очередь
  отправки может уйти при следующем подключении).
- **Только карты без рейтинга (NORating)**, набор — по возможности из Featured Artists
  (лицензия чистая, решение Q45=Б). Отбор карт делает ассистент, пользователь утверждает (Q12=А).
- **Клиент не модифицируем**: не патчим бинарник, не читаем память процесса, не внедряемся
  хуками в игру. Разрешённое: скриншот экрана (DXGI/BitBlt), захват системного звука
  (WASAPI loopback), системный/драйверный ввод, окна и хуки **ОС**.
- **Настройки lazer не трогаем** кроме временных и безобидных (режим окна/разрешение);
  всё изменённое возвращается. Аудио-калибровку игры не трогаем — свои поправки держим
  на стороне агента (решение Q23, дефолт).
- **Репозиторий — research-полигон**: README с разделом об этике (Q17=А+В).
- **Публичность:** репозиторий создаётся сразу после утверждения плана (доступ пользователя),
  публичным становится в самом конце (Q16=В).
- **Связь с разработчиками osu!** — отложенное решение (Q19), обсуждается только после
  готового демо; цель — прозрачность, а не саботаж. До этого момента никуда не пишем.
- **Роль перепроверкаа:** контур проверки — только приёмка ключевых этапов, не полный цикл (Q18=Б).

## 3. Решения пользователя (сводка ответов на 50 вопросов)

**Клиент и среда.** FPS-лимит: VSync ×2–×4 (В, уточнено пользователем: «горячий» режим, если
перегрев — переключаемся на А); режим окна: полноэкранный borderless (А); GPU: NVIDIA GTX 1650
(А) — проверить настройку в игре; питание: всегда от сети + «Макс производительность» (уже так);
звук: вывод переключён на системные динамики (Realtek), BT-наушники не используем на замерах;
фон: не закрывать (Б), при плохих замерах — закрыть; Defender: исключения для папок проекта (А).

**Карты.** Набор — 5 карт по сложности **1–3–5–7–10 звёзд** (Q8/Q11) — собран, см. §7;
отбор ассистентом, утверждение пользователем (Q12=А); этап 1 — только круги (слайдеры
пропускаем), этап 2 — все объекты (Q9); моды: NoMod (Q13=А), HR/HD/DT — опционально позже.

**Границы/публичность.** Аккаунт: выход на весь проект (Q14=А); демо: ник/имена скрывать
(Q15=А); README: research + раздел этики (Q17=А+В); репозиторий: **создан 19.10.2026 —
`https://github.com/Bileneret/osu` (private)**, публичным становится в конце (Q16=В);
перепроверка: приёмка ключевых этапов (Q18=Б); пост в сообществе и связь с разработчиками —
после демо (Q19, согласовано пользователем).

**Время и синхронизация.** loopback + калибровка — оба обязательны, расхождение в отчёт
(Q20=В); старт музыки — самый точный способ (Q21): loopback-детект + калибровка смещения;
без loopback — жить на калибровке (Q22, дефолт А). **Важно:** пользователь выключил звук на
динамиках — при нулевой громкости/mute loopback может отдавать тишину; на замерах держим
минимальную ненулевую громкость (1–2%) или детектим по факту потока (проверка в спайке).
Настройки игры менять разрешено (Q23 уточнён пользователем: «меняй что хочешь»), заводской
сброс у пользователя есть; прогоны сериями по 5 с отчётом (Q24=В); джиттер: жёстко p95 < 1 мс
(Q25=А); источник hit error: оба (наш timestamp + факт игры), расхождение в отчёт (Q26=В).

**Ввод и кинематика.** Инструмент: мышь (курсор + клик, Q27=А); сначала виртуальный ввод
(Б), для записи демо — реальный курсор (А), в проекте — возможность ручного выбора (Q28);
аварийный стоп: двойной Esc + автостоп по потере фокуса (Q29=А+В); при промахе карту
доигрываем (Q30=А); сначала идеальная игра, человекоподобность — к демо, переключаемо (Q31);
тачпад не трогаем (Q32).

**Архитектура.** Стек: спайк на Python, при провале по джиттеру — Cython-кусок, C++ ядро —
крайний случай (уточнение к Q33, рекомендую этот порядок); планировщик — отдельный процесс
с приоритетом (Q34=А); захват экрана — после прогона/по требованию (Q35=В); структура —
один пакет с выделенным ядром рефлексов (Q36, рекомендация); интерфейс — панель (Q37=Б);
логи — JSONL + сводный отчёт + логи lazer (Q38=В); тесты — писать сразу, TDD-режим (Q39=В).

**Демо.** Критерий вау: 10* на 99%+ (Q40, свой вариант); формат: видео (рекомендация при
Q41); оверлей: для записи демо (рекомендация при Q42); метрики витрины: график hit error +
сравнение с человеческими реплеями (Q43=А+Б); публикация: полный репозиторий, как три
прошлых проекта (Q44=А); музыка только из Featured Artists (Q45=Б).

**Процесс.** Ритм: длинная сессия + отчёт перепроверке + повтор (Q46=А); приёмка: скриншоты/логи
+ отчёт, живой показ по запросу (рекомендация при Q47); если 300 не стабильны: принять
достигнутое, затем драйверный ввод (Q48=Б→В); без дедлайна (Q49=А); возврат к Джарвису —
не скоро, по слову пользователя (Q50=В).

## 4. Факты о среде (проверено 19.10.2026)

| Параметр | Значение | Следствие |
|---|---|---|
| Монитор | 1920×1080: только 59/60 Гц (75 Гц — лишь на разрешениях ≤1280×1024) | кадр 16.7 мс; reactive-игра невозможна; 60 Гц — жёсткий факт |
| DPI-масштаб | 125% (120 dpi; логический рабочий стол 1536×864 при физическом 1920×1080) | обязательная поправка при переводе координат карты в экранные |
| GPU | GTX 1650 4 ГБ + Intel Iris Xe | играем на NVIDIA (проверить в настройках игры) |
| CPU/RAM | i5-11300H, 16 ГБ | достаточно; термалку контролировать (ноутбук) |
| lazer | установка `%USERPROFILE%\AppData\Local\osulazer` (468 МБ), версия **2026.1005.0** | клиент поверх которого играем |
| Данные игры | `%USERPROFILE%\AppData\Roaming\osu` (517 МБ) | карты, настройки, логи |
| Карты | в lazer — 37 мапсетов Featured Artists (1.84–6.94*); дополнительно скачан рабочий набор (1.69–10.30*), в `.\beatmaps\` | лестница 1–3–5–7–10* собрана (см. §7); «демо-карта» — kate said (10.70* по osu!) |
| Звук | вывод lazer переключён на Speakers (Realtek); динамики стоят в mute | **loopback ловит сигнал даже при mute** (проверено: RMS 0.042, peak 0.54) — пользователю слышать не нужно; в меню lazer играет превью трека, поэтому старт карты детектируем кросс-корреляцией, а не «появлением звука» |

**Физика окон попадания (osu!standard).** Полное окно «300» = `floor(80 − 6×OD) − 0.5` мс
(так считает lazer): OD8 → **±15.75 мс**, OD10 → **±9.75 мс**. При 60 Гц кадр 16.7 мс —
реакция «по картинке» не успевает даже в один кадр. Отсюда главный вывод архитектуры:

> **Тайминг берём не из пикселей, а из карты + часов.** Карта `.osu` известна заранее
> (моменты нот в миллисекундах), синхронизируемся с воспроизведением звука и ставим
> событие ввода в нужный момент. Игра судит события ввода, а не кадры.

Пиксельный путь — вспомогательный: состояние игры (пауза/конец/результат), доказательства
для приёмки, оверлей.

## 5. Архитектура (слои, с учётом решений)

1. **Чтение карты.** Парсер `.osu`: `[General]`, `[Metadata]`, `[Difficulty]`
   (`OverallDifficulty`, `ApproachRate`), `[TimingPoints]`, `[HitObjects]`
   (1 — круг, 2 — слайдер, 8 — спиннер). Берём: времена нот, координаты, длину слайдеров
   и сплайны, тайминги.
2. **Аудио-клок (основа тайминга — итоговая версия).** WASAPI loopback 48 кГц +
   кросс-корреляция с эталонным треком (`osu_agent/audio_clock.py`): позиция музыки
   непрерывно, дрейф 3 мс / 8.72 с. Сдвиг `S` (аудио-латентность + ввод) — единая
   константа; откалиброван S = 0.10 с и подтверждён контрольным прогоном
   (**149 GREAT из 150 тапов**). Визуальный детект как основа отклонён проверкой
   (квантование 60 Гц ±16.7 мс против окна ±15.75 мс) — см. `docs/prior_art_osu_bots.md`.
3. **Планировщик ударов.** Отдельный процесс (Q34=А) с повышенным приоритетом:
   `timeBeginPeriod(1)` + `QueryPerformanceCounter` + точное ожидание (спин / `NtDelayExecution`).
   Публикуем медиану, p95, максимум джиттера. Цель: p95 < 1 мс (Q25=А).
4. **Руки (ввод).** Основной путь (Q28=Б): виртуальный драйверный ввод (Interception-класс)
   — сначала прогоны без движения реального курсора; для записи демо переключаемся на
   реальный курсор (Q28=А); в проекте — ручной выбор режима. `SendInput` — запасной путь.
   **Риск, проверяемый в спайке:** lazer читает системную позицию курсора, поэтому
   «невидимый» ввод может потребовать драйвера, двигающего системный курсор; если
   виртуальный путь не сработает — переходим на драйверный с движением курсора (как в
   варианте А, он уже одобрен для демо).
5. **Кинематика.** Сначала идеальная игра (Q31=В): «пришёл в точку вовремя», для слайдеров —
   непрерывное ведение с нажатой кнопкой. Затем для демо (Q31=А): Minimum Jerk (Flash &
   Hogan), overshoot и коррекция, шум 1/f, ограничение скорости — переключаемо.
6. **Глаза (вспомогательно).** DXGI-захват (в MCP-Hands готов: `mcp_hands/screen.py`) —
   для контроля состояния и доказательств; постоянно не пишем, снимаем по требованию и
   после прогона (Q35=В).
7. **Метрики и журнал (Q38=В).** По каждой ноте: ожидаемое время, наш timestamp, hit error,
   результат (300/100/50/miss); по карте: accuracy, max combo, счёт; по системе: джиттер,
   латентность ввода. JSONL + сводный отчёт + сканы логов lazer как доказательства.
8. **Стек и структура.** Python; один пакет с выделенным ядром рефлексов (тайминг/ввод),
   чтобы ядро можно было позже переносить (Q36). При недостатке джиттера — Cython-кусок,
   затем C++ ядро (порядок рекомендован). Тесты пишем сразу (Q39=В). Интерфейс — панель
   в стиле `jarvis_panel` (Q37=Б). Прогоны сериями по 5 (Q24=В).
9. **Аварии и безопасность (Q29=А+В).** Двойной Esc — аварийное торможение; автостоп при
   потере фокуса окна игры/таймауте; при промахе карту доигрываем до конца (Q30=А) для
   полной статистики.

## 8. Спайк 2–3 дня (критерий «готово»)

**Прогресс: Этап 2 идёт.** Полное покрытие карты реализовано: `osu_agent/player.py`
играет круги (тап), **слайдеры (ведение по пути с нажатой кнопкой)** и **спиннеры
(вращение)**. Полный прогон `pearto's Easy`: **124 524 очка, точность 80,55%,
139 GREAT, SLIDER TICK 39/49, SLIDER END 54/86, SPINNER SPIN 11/11** (было 0 по всем
слайдерным/спиннерным метрикам). Условия проверки Этапа 2 закрыты (неблокирующий KeyUp,
фоновый клок, чередование Z/X, ядро слайдеров). Отчёт: `/spike_v1/06_stage2_conditions_report.md`.
**Остаточные задачи:** сократить пропуск начала карты (калибровка ~4–6 с), точность
ведения хвостов слайдеров, спиннер-бонусы; затем серии на 3*/5*.

**День 1 — карта и ввод.**
- парсер `.osu` (круги, тайминги, сплайны); распределение интервалов;
- сборка рабочего набора карт (§7) с утверждением пользователя;
- **проверка ввода в lazer**: сначала виртуальный драйверный путь, при неудаче — `SendInput`;
  критерий — по игровому счётчику/результату, а не «на глаз»;
- учёт DPI 125% в координатной трансформации (контрольный тест «попал в кружок»).
- *Готово, если:* карта разобрана, ввод доходит до игры любым из путей (или честный отказ).

**День 2 — время.**
- WASAPI loopback (детект старта потока) + калибровка смещения;
- планировщик: `timeBeginPeriod(1)` + спин; замер джиттера в микросекундах (1000 замеров).
- *Готово, если:* джиттер медианы < 1 мс, p95 < 3 мс (жёсткая цель проекта — p95 < 1 мс,
  достигаем итерациями).

**День 3 — первый хит.**
- проиграть фрагмент карты (первые ~20 нот) с попаданием в 300;
- собрать hit error по нотам (оба источника), скриншот/видео приёмки, запись в журнал.
- *Готово, если:* ≥18 из 20 нот в 300 (полуокно ±15.75 мс при OD8).

**Стоп-условия спайка (меняем подход, а не «дожимаем»):**
- ввод не доходит ни виртуальным путём, ни `SendInput` → драйверный ввод с движением
  курсора (вариант А), при неудаче — отдельная учётная запись/сессия;
- аудио-клок недоступен или дрейфует → живём на калибровке с периодической перекалибровкой;
- джиттер > 5 мс после всех мер → приоритеты процессов/изоляция ядер, при неудаче —
  честный отчёт и попытка Cython-куска.

## 11. Риски и неизвестные

1. **Ввод** — снят: синтетические клики/клавиши доходят и в интерфейс, и в геймплей
   (новые риски — точность тайминга, см. ниже).
2. **Драйвер:** виртуальный драйверный ввод пока не потребовался (SendInput работает);
   вопрос установки драйвера — отложен до реальной необходимости.
3. **Нестабильность аудио-часов lazer (главный блокер, найден в день 3).**
   BASS + экспериментальный WASAPI на устройстве Realtek: в логе `Playback discrepancy`
   (~304 мс, 5 попыток) → остановка воспроизведения; сдвиг «время карты ↔ реальный звук»
   ведёт себя как плавающая величина. План: отключить экспериментальный WASAPI
   (`AudioUseExperimentalWasapi = False`), проверить устройства (Realtek без mute /
   виртуальное Steam), только затем калибровка S и первый хит.
4. **Кнопки главного меню lazer** не активируются одиночным кликом (анимация карусели);
   рабочий рецепт — двойной клик. Учесть в автоматизации меню.
5. **Notelock:** клик в пределах 400 мс до ноты = miss (нота «съедается»); долбёжка
   не работает принципиально, нужен одиночный точный тап (+лаг исполнения ~23 мс).
5. **Аудио-латентность и дрейф** — дрейф клока измерен (3 мс на 8.7 с — отлично);
   остаточный риск — смена устройства/драйвера. Mute не мешает (проверено).
6. **60 Гц панель** — ограничивает визуальную обратную связь, но не тайминг (§4).
7. **Термалка ноутбука** — длинные серии прогонов греют GPU (FPS-лимит ×2–×4); следим за
   троттлингом, при перегреве переключаемся на VSync.
8. **lazer обновляется** — работаем «снаружи», обновления не ломают архитектуру, но
   требуют проверки после крупных апдейтов.
9. **Музыкальная лицензия демо** — карты лестницы не Featured Artists; для публичного
   видео решаем: без звука / замена / только FA-карты (см. §12).
10. **Фон/уведомления** — дают джиттер и кражу фокуса; автостоп по фокусу включён.
    При потере фокуса lazer **паузит загрузку карты** и сворачивается
    (`MinimiseOnFocusLossInFullscreen = True`) — на прогонах держать фокус или отключить.
11. **Начало карты** — решено клоком: нестабильная задержка старта больше не мешает
    (позиция музыки определяется по звуку, а не по времени клика Play).
12. **Этика** — играем офлайн и честно показываем цифры; «человекоподобие» лишь как
    опция визуализации для демо, без претензии на «неотличимость от человека».
