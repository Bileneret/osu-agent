# Спайк, день 3: отчёт — калибровка, найденные проблемы

**Дата:** 19.10.2026, ночь. **Статус:** день 3 закрыт. Первый хит в 300 не достигнут;
найдена системная причина — нестабильность аудио-часов lazer. Статус спайка: **техническая
работоспособность доказана, стабильное попадание требует стабилизации аудио-движка.**

## Что сделано

1. **Восстановление после сбоя.** Сеанс застал игру в зависшем состоянии: lazer
   остановил воспроизведение (`Playback discrepancy detected` ×5 → `System audio playback
   is not working as expected. Please check your audio drivers`). Игра перезапущена,
   динамики выведены из mute (громкость 2%).
2. **Обход главного меню lazer.** Кнопки главного меню не активируются одиночным кликом
   (панель анимируется, при клике часто «листается» ряд). Рабочий рецепт: **двойной клик**
   по кнопке; из главного меню так открыт song select. Зафиксировано для автоматизации.
3. **Полный прогон карты** (No Fail): прогресс 100%, **1 MEH, 162 MISS, макс. комбо 1,
   точность 0.37%** (скриншот экрана результатов — доказательство в пакете).
4. **Калибровка сдвига S** двумя методами:
   - серии тапов по нотам с гипотезами S ∈ [0.60 … 1.98] (36 тапов за два прогона) —
     попаданий практически нет;
   - детект появления ноты на экране + тап через preempt (1440 мс, AR3) — детектор
     поймал не ноту (яркость от курсора/фона), метод требует калибровки порогов.

## Ключевая находка дня

**Аудио-часы lazer нестабильны на текущей конфигурации** (BASS + экспериментальный WASAPI,
устройство Realtek): в логе — рассинхронизация воспроизведения (дискрепанс ~304 мс,
5 попыток) и последующая остановка. Вероятное следствие: связь «время карты (таймер игры)
↔ позиция реального звука (loopback)» непостоянна — то есть сдвиг S **не константа**,
а плавающая величина. Это объясняет, почему одиночное попадание (день 2) не
воспроизводится при точном сканировании S.

Косвенные подтверждения:
- смещение таймера карты относительно клока в разных замерах: ~+1.0 с (день 2),
  затем расхождения, мешающие сканированию (день 3);
- loopback ловит звук даже при mute, но сам движок lazer при этом работает нестабильно.

## План стабилизации (следующая сессия, до калибровки)

1. Переключить аудио-движок lazer: отключить «экспериментальный WASAPI»
   (`AudioUseExperimentalWasapi = False`, в UI — «Включить устаревший звуковой движок»);
   сравнить стабильность (лог: отсутствие `Playback discrepancy`).
2. Проверить альтернативное устройство вывода (физическое Realtek без mute / виртуальное
   Steam Streaming Speakers) — искать конфигурацию без дискрепанса.
3. Только после стабильного аудио — повторить измерение S (сравнение таймера карты
   и позиции loopback на нескольких точках) и калибровку тапами.

## Поиск готовых решений (по просьбе пользователя)

Проведён обзор открытых osu!-ботов (подробно — `docs/prior_art_osu_bots.md`).
**Ключевое:** ни один бот, играющий по `.osu` без чтения памяти (osu-pilot 13★,
Py-OsuAuto), не использует аудио-клок. Схема у всех: отметка старта (нажатие клавиши
в момент появления первого круга) + калибруемый offset + таймлайн карты.
Вывод: переводим основу тайминга на **визуальную отметку (detект approach circle)
+ калибруемый offset по hit error**; аудио-клок остаётся вспомогательным.
