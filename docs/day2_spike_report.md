# Спайк, день 2: отчёт — аудио-клок, тапы, джиттер

**Дата:** 19.10.2026, ночь. **Статус:** день 2 закрыт. Главный вопрос спайка закрыт:
синтетические тапы доходят до геймплея и засчитываются.

## 1. Аудио-клок (появился, работает)

**Модуль:** `osu_agent/audio_clock.py` — захват WASAPI loopback (библиотека soundcard)
+ поиск позиции в треке нормированной кросс-корреляцией с эталонным mp3 карты.

- Разбиение записи на окна (0.8 с), суммирование NCC по окнам — устойчивость к шуму
  и разрывам записи (в loopback Realtek периодически бывают `data discontinuity`).
- Грубый поиск на 8 кГц с антиалиасингом (децимация усреднением), разрешение 0.125 мс.
- **Проверка точности:** два замера с интервалом 8.72 с дали разницу позиций
  **8.717 с** — расхождение 3 мс, дрейфа нет.
- Score (нормированная корреляция): 0.3–0.6 на живом звуке игры
  (сигнал искажают аудио-«улучшайзеры» Realtek — Nahimic и подобные; для локации
  этого достаточно, пик выделяется). На чистом сигнале (эталон против себя) — 1.000,
  с шумом амплитуды 0.15 — 0.976.)
- **Ключевая находка:** loopback получает звук **даже при mute устройства** — пользователю
  слышать ничего не нужно, клоку данные идут.
- **Особенность:** в меню lazer играет превью трека, поэтому «детект появления звука»
  не работает — нужна именно локация по позиции (сделано).

## 2. Тапы Z в геймплее — РАБОТАЮТ

Закрыт главный риск спайка. Доказательства (по скриншотам, не «на глаз»):

1. **Оверлей нажатий lazer** отображает клавишу «Z» во время игры (скрин 49).
2. После серии прицельных тапов в записи результата: **макс. комбо 1x, точность 0.15%**
   (скрин 51), на паузе — «Точность: 0,91%», прогресс 81%.

То есть тап-события SendInput доходят до игрового процесса и судятся игрой.

## 3. Что выяснено про тайминг (важно для следующего этапа)

1. **Notelock:** непрерывная долбёжка не работает принципиально — клик в пределах
   400 мс до ноты засчитывается как miss и «съедает» ноту. Нужен один точный тап.
2. **Системный сдвиг S ≈ 1.0 с**: время карты (по таймеру игры) опережает позицию mp3
   (по клоку) примерно на секунду. Причина не установлена (аудио-латентность вывода
   при experimental WASAPI или особенность lazer); калибруется.
3. **Лаг исполнения тапа:** фактическое нажатие происходит на ~23 мс позже расчётного
   момента (спиновое ожидание + SendInput). Учитывать при планировании.
4. Из 10 сканирующих тапов с разными гипотезами S (0.0–1.8) одно попадание
   засчиталось — S в окрестности 1.0 с подтверждается, но требует уточнения серией.

## 4. Джиттер планировщика — критерий выполнен с запасом

Замер (`spike/jitter_test.py`): `timeBeginPeriod(1)` + сон до цели минус 1.2 мс + спин,
500 событий с интервалом 10 мс:

| метрика | значение |
|---|---|
| медиана \|ошибка\| | **0.2 мкс** |
| p95 \|ошибка\| | **9.5 мкс** |
| p99 | 1.34 мс |
| максимум | 15.2 мс (единичный выброс) |

Критерий дня 2 (медиана < 1 мс, p95 < 3 мс) — выполнен; выполнена и жёсткая цель
проекта (p95 < 1 мс). Выбросы лечатся отдельным процессом с приоритетом (по плану, §5.3).
